# SMP-233: Kiểm tra bộ lọc quá hạn (overdue) gồm cả processing và processed trễ hạn sau đồng bộ DB

1. **Mã số test case:** SMP-233
2. **Tên test case:** Kiểm tra bộ lọc quá hạn (overdue) gồm cả processing và processed trễ hạn sau đồng bộ DB
3. **Project:** Spring Boot Backend
4. **Chức năng:** Đồng bộ hạn xử lý và lọc báo cáo quá hạn
5. **Loại kiểm thử:** Repository Integration Test
6. **Mô tả test case:** Gọi deadlineSyncInitializer.syncMissingDeadlines() (cập nhật DB thật), xác nhận không còn report ngoài rejected bị thiếu deadline, rồi kiểm tra findAllFiltered, findMyReports và findStaffAssignedFiltered với bộ lọc overdue=true trả về cả report processing quá hạn lẫn processed hoàn tất trễ hạn.
7. **Mục đích kiểm thử:** Xác minh đồng bộ deadline bị thiếu và các truy vấn Repository lọc báo cáo quá hạn hoạt động đúng cho Admin, Client và Staff.
8. **Điều kiện tiên quyết:** MySQL và Redis đang chạy; dữ liệu DB thật đang có sẵn ít nhất 1 report processing quá hạn và ít nhất 1 report processed hoàn tất trễ hạn.
9. **Các bước kiểm thử:**

| Bước | Thao tác | Input | Kết quả kỳ vọng |
|---|---|---|---|
| 1 | Gọi deadlineSyncInitializer.syncMissingDeadlines() và kiểm tra reportRepository.findByDeadlineIsNullAndStatusNot(EReportStatus.rejected). | Dữ liệu DB hiện hành (có tác động ghi/cập nhật DB thật bởi syncMissingDeadlines) | Danh sách report khác rejected có deadline == null có kích thước bằng 0. |
| 2 | Gọi reportRepository.findAllFiltered(..., isOverdue=true, now=LocalDateTime.now(), PageRequest.of(0, 100)). | overdueOnly=true, now=LocalDateTime.now(), PageRequest(0, 100) | adminOverdue.getTotalElements() > 0; chứa ít nhất 1 report status=processing và ít nhất 1 report status=processed. |
| 3 | Nếu tìm thấy sampleOwnerId (user != null) thì gọi reportRepository.findMyReports(..., overdueOnly=true); nếu tìm thấy sampleStaffId (assignedStaff != null) thì gọi reportRepository.findStaffAssignedFiltered(..., overdueOnly=true). | sampleOwnerId và sampleStaffId đầu tiên từ adminOverdue (nếu khác null) | clientOverdue.getTotalElements() > 0 (nếu có owner); staffOverdue không rỗng (nếu có staff). |

10. **Input từng bước:**
   - Bước 1: Dữ liệu DB hiện hành (có tác động ghi/cập nhật DB thật bởi syncMissingDeadlines)
   - Bước 2: overdueOnly=true, now=LocalDateTime.now(), PageRequest(0, 100)
   - Bước 3: sampleOwnerId và sampleStaffId đầu tiên từ adminOverdue (nếu khác null)
11. **Kỳ vọng từng bước:**
   - Bước 1: Danh sách report khác rejected có deadline == null có kích thước bằng 0.
   - Bước 2: adminOverdue.getTotalElements() > 0; chứa ít nhất 1 report status=processing và ít nhất 1 report status=processed.
   - Bước 3: clientOverdue.getTotalElements() > 0 (nếu có owner); staffOverdue không rỗng (nếu có staff).
12. **File test tương ứng:** `SmartSpace_Backend/src/test/java/com/vn/smart_space/SmartSpaceApplicationTests.java`
13. **Ghi chú:** CẢNH BÁO TÁC ĐỘNG DB & PHỤ THUỘC DỮ LIỆU: Test gọi deadlineSyncInitializer.syncMissingDeadlines() làm thay đổi dữ liệu DB thật (cập nhật cột deadline). Ngoài ra các assertion phụ thuộc dữ liệu DB đang có sẵn cả report processing quá hạn và report processed trễ hạn; nếu thiếu một trong hai loại thì test sẽ fail.
