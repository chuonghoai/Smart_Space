# SMP-193: Kiểm tra phân quyền Client 403 và luồng CRUD News của Admin

1. **Mã số test case:** SMP-193
2. **Tên test case:** Kiểm tra phân quyền Client 403 và luồng CRUD News của Admin
3. **Project:** Spring Boot Backend
4. **Chức năng:** Quản lý Tin tức (/news)
5. **Loại kiểm thử:** API Integration Test (Live HTTP)
6. **Mô tả test case:** Kiểm tra Client (ROLE_client) bị chặn 403 khi tạo tin tức, sau đó Admin (ROLE_admin) thực hiện đầy đủ vòng đời CRUD: tạo tin tức (201, lấy data.id), xem chi tiết công khai GET /news/{id} (200), cập nhật PUT /news/{id} (200) và xóa DELETE /news/{id} (200).
7. **Mục đích kiểm thử:** Xác minh cơ chế phân quyền CUD tin tức chỉ dành cho Admin và tính hoạt động xuyên suốt của các endpoint CRUD /news.
8. **Điều kiện tiên quyết:** Backend đang chạy tại http://localhost:8989 (nếu không kết nối được socket, @BeforeAll chỉ in thông báo và @Test return sớm); JWT HS512 giả lập cho admin-test-id (ROLE_admin) và client-test-id (ROLE_client) ký bằng SIGNER_KEY.
9. **Các bước kiểm thử:**

| Bước | Thao tác | Input | Kết quả kỳ vọng |
|---|---|---|---|
| 1 | Kiểm tra socket tới localhost:8989 (timeout 1500ms) | Socket localhost:8989 | Nếu backend đang chạy thì tiếp tục bước 2; nếu không chạy thì return sớm và thoát test. |
| 2 | Client gửi POST /news với JSON title, content, image_urls | Token client-test-id (ROLE_client), payload tạo tin tức | HTTP 403 Forbidden. |
| 3 | Admin gửi POST /news với payload tạo tin tức | Token admin-test-id (ROLE_admin), payload tạo tin tức | HTTP 201 Created; data.id khác null và không rỗng. |
| 4 | Gửi GET /news/{newsId} (không đính kèm token) | newsId lấy từ bước 3 | HTTP 200 và body chứa "Tin tức an ninh môi trường". |
| 5 | Admin gửi PUT /news/{newsId} với tiêu đề và nội dung mới | Token admin-test-id, JSON cập nhật | HTTP 200. |
| 6 | Admin gửi DELETE /news/{newsId} | Token admin-test-id, newsId | HTTP 200. |

10. **Input từng bước:**
   - Bước 1: Socket localhost:8989
   - Bước 2: Token client-test-id (ROLE_client), payload tạo tin tức
   - Bước 3: Token admin-test-id (ROLE_admin), payload tạo tin tức
   - Bước 4: newsId lấy từ bước 3
   - Bước 5: Token admin-test-id, JSON cập nhật
   - Bước 6: Token admin-test-id, newsId
11. **Kỳ vọng từng bước:**
   - Bước 1: Nếu backend đang chạy thì tiếp tục bước 2; nếu không chạy thì return sớm và thoát test.
   - Bước 2: HTTP 403 Forbidden.
   - Bước 3: HTTP 201 Created; data.id khác null và không rỗng.
   - Bước 4: HTTP 200 và body chứa "Tin tức an ninh môi trường".
   - Bước 5: HTTP 200.
   - Bước 6: HTTP 200.
12. **File test tương ứng:** `SmartSpace_Backend/src/test/java/com/vn/smart_space/controller/news/NewsIntegrationTest.java`
13. **Ghi chú:** Cảnh báo quan trọng: Test tự kiểm tra socket port 8989 trong @BeforeAll (chỉ in log, không fail) và đầu @Test (if (!isRunning) return;), nên khi chạy Maven offline lúc backend chưa chạy sẽ tạo ra PASS giả (false pass). Đối chiếu repo: yêu cầu phân công ban đầu có ghi chú "không được đăng ký trong testapi.ps1", tuy nhiên kiểm tra thực tế file testapi.ps1 (dòng 64-67) cho thấy class này hiện ĐÃ được đăng ký dưới lệnh "NewsIntegration".
