# SMP-279: Kiểm tra introspect trả về hợp lệ cho access token của user đang hoạt động

1. **Mã số test case:** SMP-279
2. **Tên test case:** Kiểm tra introspect trả về hợp lệ cho access token của user đang hoạt động
3. **Project:** Spring Boot Backend
4. **Chức năng:** Xác thực & Bảo mật tài khoản (AuthenticationService)
5. **Loại kiểm thử:** Unit Test
6. **Mô tả test case:** Kiểm tra introspect khi access token hợp lệ, jti chưa bị invalidate và Redis không có khóa "blocked_user:user-1" thì trả về isValid() == true.
7. **Mục đích kiểm thử:** Xác minh access token của người dùng không bị khóa vẫn được đánh giá hợp lệ qua introspect.
8. **Điều kiện tiên quyết:** Mock jwtService.verifyToken("at") trả về SignedJWT(jti="jti-1", userId="user-1", tokenType="access"). Mock invalidatedTokenRepository.existsById("jti-1") = false và stringRedisTemplate.hasKey("blocked_user:user-1") = false.
9. **Các bước kiểm thử:**

| Bước | Thao tác | Input | Kết quả kỳ vọng |
|---|---|---|---|
| 1 | Stub token access hợp lệ và cờ blocked_user trong Redis bằng false | token="at", jti="jti-1", userId="user-1", existsById=false, hasKey("blocked_user:user-1")=false | Mock trả về chưa invalidate và không có cờ khóa |
| 2 | Gọi authenticationService.introspect(IntrospectRequest.builder().token("at").build()) | IntrospectRequest(token="at") | Response có isValid() == true |

10. **Input từng bước:**
   - Bước 1: token="at", jti="jti-1", userId="user-1", existsById=false, hasKey("blocked_user:user-1")=false
   - Bước 2: IntrospectRequest(token="at")
11. **Kỳ vọng từng bước:**
   - Bước 1: Mock trả về chưa invalidate và không có cờ khóa
   - Bước 2: Response có isValid() == true
12. **File test tương ứng:** `SmartSpace_Backend/src/test/java/com/vn/smart_space/service/auth/AuthenticationServiceSecurityTest.java`
13. **Ghi chú:** Thuộc nhóm @Nested BlockedAccount.
