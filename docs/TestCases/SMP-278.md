# SMP-278: Kiểm tra introspect trả về không hợp lệ cho access token của user bị đánh dấu khóa

1. **Mã số test case:** SMP-278
2. **Tên test case:** Kiểm tra introspect trả về không hợp lệ cho access token của user bị đánh dấu khóa
3. **Project:** Spring Boot Backend
4. **Chức năng:** Xác thực & Bảo mật tài khoản (AuthenticationService)
5. **Loại kiểm thử:** Unit Test
6. **Mô tả test case:** Kiểm tra introspect khi access token chưa nằm trong bảng invalidatedTokenRepository nhưng Redis có khóa "blocked_user:user-1" thì trả về isValid() == false.
7. **Mục đích kiểm thử:** Xác minh cơ chế thu hồi tức thì qua cờ Redis khiến access token còn hạn của user vừa bị khóa trở thành không hợp lệ.
8. **Điều kiện tiên quyết:** Mock jwtService.verifyToken("at") trả về SignedJWT(jti="jti-1", userId="user-1", tokenType="access"). Mock invalidatedTokenRepository.existsById("jti-1") = false và stringRedisTemplate.hasKey("blocked_user:user-1") = true.
9. **Các bước kiểm thử:**

| Bước | Thao tác | Input | Kết quả kỳ vọng |
|---|---|---|---|
| 1 | Stub token access hợp lệ chưa bị invalidate và cờ blocked_user trong Redis bằng true | token="at", jti="jti-1", userId="user-1", existsById=false, hasKey("blocked_user:user-1")=true | Mock sẵn sàng phản hồi token không bị blacklist JTI nhưng có cờ blocked_user |
| 2 | Gọi authenticationService.introspect(IntrospectRequest.builder().token("at").build()) | IntrospectRequest(token="at") | Response có isValid() == false |

10. **Input từng bước:**
   - Bước 1: token="at", jti="jti-1", userId="user-1", existsById=false, hasKey("blocked_user:user-1")=true
   - Bước 2: IntrospectRequest(token="at")
11. **Kỳ vọng từng bước:**
   - Bước 1: Mock sẵn sàng phản hồi token không bị blacklist JTI nhưng có cờ blocked_user
   - Bước 2: Response có isValid() == false
12. **File test tương ứng:** `SmartSpace_Backend/src/test/java/com/vn/smart_space/service/auth/AuthenticationServiceSecurityTest.java`
13. **Ghi chú:** Thuộc nhóm @Nested BlockedAccount.
