# SMP-257: Kiểm tra proposalBlockedReason cho trạng thái bị khóa và đã có đề xuất chờ

1. **Mã số test case:** SMP-257
2. **Tên test case:** Kiểm tra proposalBlockedReason cho trạng thái bị khóa và đã có đề xuất chờ
3. **Project:** Spring Boot Backend
4. **Chức năng:** Điều kiện đề xuất khóa, bộ lọc và bộ đếm
5. **Loại kiểm thử:** Unit Test
6. **Mô tả test case:** Kiểm tra AccountLockRequestServiceImpl.proposalBlockedReason(User) trả về "not_active" khi user đang ở trạng thái blocked và trả về "already_pending" khi user active nhưng đang có đề xuất pending.
7. **Mục đích kiểm thử:** Xác minh hàm tính lý do chặn nút tạo đề xuất khóa trên UI/API hoạt động đúng thứ tự kiểm tra trạng thái.
8. **Điều kiện tiên quyết:** Tạo user("user-1", ERole.client, EUserStatus.blocked) và user("user-1", ERole.client, EUserStatus.active); stub requestRepository.existsByTargetIdAndStatus("user-1", pending) trả về true cho trường hợp thứ hai.
9. **Các bước kiểm thử:**

| Bước | Thao tác | Input | Kết quả kỳ vọng |
|---|---|---|---|
| 1 | Gọi service.proposalBlockedReason(...) với client bị blocked | user("user-1", ERole.client, EUserStatus.blocked) | Trả về "not_active" |
| 2 | Gọi service.proposalBlockedReason(...) với client active đã có đề xuất pending | user("user-1", ERole.client, EUserStatus.active), existsByTargetIdAndStatus=true | Trả về "already_pending" |

10. **Input từng bước:**
   - Bước 1: user("user-1", ERole.client, EUserStatus.blocked)
   - Bước 2: user("user-1", ERole.client, EUserStatus.active), existsByTargetIdAndStatus=true
11. **Kỳ vọng từng bước:**
   - Bước 1: Trả về "not_active"
   - Bước 2: Trả về "already_pending"
12. **File test tương ứng:** `SmartSpace_Backend/src/test/java/com/vn/smart_space/service/admin/AccountLockRequestServiceImplTest.java`
13. **Ghi chú:** Tên test method: Eligibility.blockedReasons_inactiveAndPending.
