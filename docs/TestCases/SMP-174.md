# SMP-174: Mở khóa tài khoản đang hoạt động hoặc thiếu lý do bị từ chối 400

1. **Mã số test case:** SMP-174
2. **Tên test case:** Mở khóa tài khoản đang hoạt động hoặc thiếu lý do bị từ chối 400
3. **Project:** Spring Boot Backend
4. **Chức năng:** Mở khóa tài khoản người dùng (/admin/users/{id}/unlock)
5. **Loại kiểm thử:** API Integration Test (Live HTTP)
6. **Mô tả test case:** Kiểm tra Admin gửi PUT /admin/users/u2/unlock nhận HTTP 400 khi tài khoản client u2 đang ở trạng thái hoạt động hoặc khi trường reason rỗng.
7. **Mục đích kiểm thử:** Đảm bảo API mở khóa chỉ chấp nhận mở khóa tài khoản đang bị khóa và bắt buộc có lý do mở khóa.
8. **Điều kiện tiên quyết:** Backend đang chạy tại -Dsmartspace.baseUrl (mặc định http://localhost:8989); trong seed_data.sql, client u2 đang ở trạng thái hoạt động; JWT admin u1 ký bằng SIGNER_KEY.
9. **Các bước kiểm thử:**

| Bước | Thao tác | Input | Kết quả kỳ vọng |
|---|---|---|---|
| 1 | Admin gửi PUT /admin/users/u2/unlock với lý do hợp lệ cho tài khoản đang hoạt động u2 | {"reason":"Đã xác minh lại thông tin"} | HTTP 400 Bad Request. |
| 2 | Admin gửi PUT /admin/users/u2/unlock với reason rỗng | {"reason":""} | HTTP 400 Bad Request. |

10. **Input từng bước:**
   - Bước 1: {"reason":"Đã xác minh lại thông tin"}
   - Bước 2: {"reason":""}
11. **Kỳ vọng từng bước:**
   - Bước 1: HTTP 400 Bad Request.
   - Bước 2: HTTP 400 Bad Request.
12. **File test tương ứng:** `SmartSpace_Backend/src/test/java/com/vn/smart_space/controller/admin/AccountLockRequestManagementTest.java`
13. **Ghi chú:** Không làm thay đổi trạng thái tài khoản u2. Class này chưa đăng ký trong testapi.ps1.
